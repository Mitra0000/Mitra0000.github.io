Precision Renderer Memory Diagnostics

A deterministic test suite designed to differentiate the good and bad revisions of WebView by measuring peak concurrent allocation, post-GC reclamation, and cache-eviction behavior.

Diagnostic Setup: To enable direct memory measurement, run Chrome/WebView with --enable-precise-memory-info and --expose-gc. If window.gc is exposed, this test will automatically trigger deterministic garbage collection cycles.

1. ObjectTemplate Peak & GC Test

Launches 30 contexts concurrently, accesses 40 DOM interfaces in each, captures peak concurrent allocation, then terminates them and triggers synchronous GC.

In the good revision, peak memory is low and returns to baseline. In the bad revision, peak memory is extremely high due to duplication.

2. Cache Eviction Diagnostic

Loads 50 unique data: URI images (1MB total), then forces cache pressure by fetching 10MB of large standard image resources to trigger eviction.

In the good revision, standard cache pressure evicts the data URIs. In the bad revision, they are strongly pinned and fail to evict.
