Chromium Renderer Memory Regression stress-test

Designed to isolate and reproduce the 10x Renderer Memory Regression spiked in Fitbit WebView due to ObjectTemplate duplication, CallbackHolder cppgc deferred lifetimes, and eager Data URI cache pinning.

Target Platforms: This stress-test is especially diagnostic inside Android WebView or Chrome on Android. In Chrome/Chromium, you can open DevTools Performance monitor or monitor `chrome://tracing` and task manager while running the tests.

1. ObjectTemplate Duplication

Creates many short-lived iframes. In each iframe, it instantiates 50+ unique DOM classes (Div, Canvas, Video, Audio, Button, Table, etc.).

Regressed code duplicate-compiles ObjectTemplates per-context, ballooning the V8 heap. Clean code shares templates per-isolate.

2. CallbackHolder cppgc Deferral

Creates transient elements and registers thousands of event listener callbacks bound to complex closures, then immediately drops references.

Regressed code relies on cppgc deferred sweeper cycles to delete callbacks, keeping bound closures in memory. Clean code deletes them instantly.

3. Eager Data URI Cache Pinning

Queries MemoryCache with thousands of unique generated inline data URI resources.

Regressed code automatically touch-adds and pins every queried data URI in MemoryCache's strong ref list, blocking eviction.
